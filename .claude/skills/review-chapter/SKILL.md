# /review-chapter

章を3つの観点から並列に査読し、報告を `docs/reviews/` に書く。**章そのものは編集しない**(直すかはユーザーが決める)。

使い方: `/review-chapter chapters/study1.tex`(章のファイルかラベル。省略したら、どの章かを確かめる)

## 手順

1. **材料を読む。**
   - 章の本文全体、`draft/notation.tex`、`docs/thesis-plan.md`(この章が答える研究課題)、`docs/guardrails.md`
   - `research.json` のこの章の行(`id`・`source`・`paper`・`paper_status`)
   - `projects/<id>/README.md`(要約カードと図表の元)、`values.tex`(各値の元のコメント)、`figures/`・`tables/`
   - 研究リポジトリのクローン `<path>` があれば(`external/<repo>` など)、出典のコミットの中身を
     `git -C <path> show <sha>:<file>` で読む(作業ツリーは出典と違うことがある)。無ければ「確かめられない」と書く
   - `make pdf` の後の `python3 tools/thesis_check.py --all` のうち、この章の所見

2. **並列のサブエージェントで査読する。** 3系統を**並列**に起動し、各エージェントに章の全文と必要な材料を渡して、
   重大 / 要修正 / 軽微 の印と原文の引用を付けた所見を返させる。
   1. **論証の構成**: 各節が章の主張を進めているか、序論・方法・結果・考察の流れ、冒頭の問いと結果・考察の対応、
      まとめの節が答えた研究課題と次の章へのつながりを述べているか
   2. **本文と根拠の整合**:
      - 本文の主張がすべて `projects/<id>/` の図表・値とカードの「主な結果」に遡れるか
      - 本文に手で書いた数値が無いか。`\val` の各値が `values.tex` のコメントの元(出典のコミットの CSV・論文)と
        一致し、本文の言い回し(増えた・有意など)と矛盾しないか
      - 主張がカードの「言えないこと・注意」を越えていないか。撤回・訂正された結果や `docs/guardrails.md` の
        撤回した主張に頼っていないか
      - 論文に基づく章なら、前書き(発表の状況、引用、著者の貢献、転載の許諾、発表版との違い)が `research.json`
        と `draft/frontmatter/publications.tex` と一致しているか
      - 図表の参照の順序、図表の説明と本文の一致
   3. **明瞭さと文体**: あいまい・冗長な表現、時制の一貫性、用語・記号が `notation.tex`・略語一覧と一致しているか

3. **引用の過不足を挙げる。** 出典が必要なのに引用の無い主張を挙げる。**引用を捏造しない**(候補は DOI で原典を
   確かめたものだけ)。

4. **報告を書く。** `docs/reviews/YYYY-MM-DD-<章の slug>.md` に、総評(3行以内)、重大 / 要修正 / 軽微 ごとの所見
   (「原文の引用 → 修正案」)、撤回・訂正された結果に頼る主張(無ければ「なし」)、値の照合の結果、足りないもの
   (写していない図表、研究リポジトリで作ってもらう数値)を書く。上位3件をその場で要約し、報告のパスを示す。
