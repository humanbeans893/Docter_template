# /review-thesis

論文全体を、章をまたいだ一貫性の観点から並列に査読し、報告を `docs/reviews/YYYY-MM-DD-thesis.md` に書きます。
**原稿は編集しません**(直すかどうかはユーザーが決めます)。1章の中身の査読は `/review-chapter` を使います。

使うとき: 全体を指導教員・審査員に送る前、章を足した・大きく直した後、提出の前。

## 手順

### 1. 材料を集める

- `docs/thesis-plan.md`(主張・RQ・貢献・章構成マップ・その他の構成要素・「全体の一貫性チェック」)
- `draft/main.tex` の章の並び、`draft/frontmatter/`(和英の要旨、謝辞、`publications.tex`)、各章、`draft/backmatter/`、
  `draft/notation.tex`、略語・記号の一覧
- `draft/values.tex` と登録された値のファイル(`projects/<study>/result/tables/<name>.tex`・`.csv`)
- 各スタディの `projects/<study>/experiments/EXP_SUMMARY.md`(と `EXP_ARCHIVE.md`)、`docs/guardrails.md`
- 章の生成物の由来記録(`experiment` と `sources`)が指す実験の `summary.md`(方法を点検するときだけ
  `README.md` と `run.py`)
- 検査の結果: `make pdf` の後に `python3 tools/thesis_check.py --all`。所見のうち E8・W11・W14・W15・W17 と、
  I3(R3 の生成物)の一覧を控える

### 2. 並列のサブエージェントで査読する

Task ツールで次の観点を**並列**に起動する。各エージェントには必要な章と材料を渡し、重大 / 要修正 / 軽微 の印、
該当箇所(ファイルと行、またはラベル)、原文の引用、修正案を付けた所見を返させる。

1. **研究課題と答え**: 序論の各 RQ に、結論の章が答えを出しているか。答えの根拠の章・図表が `\cref` で
   示されているか。`docs/thesis-plan.md` の RQ の表(答える章・根拠)と原稿が一致しているか。答えの無い RQ、
   RQ に対応しない章が無いか。
2. **要旨・結論と結果**: 和英の要旨と結論に書かれた結果・数値が、各章の結果と一致しているか。数値が `\val{…}` で
   章と同じキーを読んでいるか(手で書いた数値を挙げる)。和文要旨と英文要旨の内容が食い違っていないか。
3. **貢献と根拠**: `docs/thesis-plan.md` の各貢献と、序論・結論で主張する貢献が、章・図表・値・論文で裏付けられて
   いるか。主張が根拠の実験の `summary.md` の答えと「言えないこと」を越えていないか。根拠の実験の状態が
   `撤回`・`中止`・`置き換え`・`進行中` でないか(索引と `summary.md`)。`docs/guardrails.md` の撤回した主張に
   頼っていないか。
4. **用語と記号**: 用語・記号・略語が `notation.tex`・一覧と一致し、章によって定義や表記が揺れていないか。
   同じ量に別の記号、別の量に同じ記号を使っていないか。
5. **章のつながり**: 各スタディの章の「Chapter Summary」が答えた RQ と次の章へのつながりを述べているか。
   序論の構成の説明が実際の章の並びと一致しているか。背景・方法の重複が章をまたいで繰り返されていないか。
6. **業績と章**: `frontmatter/publications.tex` の業績と、各章の冒頭の出版情報(完全な引用・著者の貢献・
   転載の許諾・発表版との違い)が一致しているか。`thesis-plan.md` の「基になる論文」と一致しているか。

### 3. R3 の一覧

`make check` の I3 から、R3 の生成物(そのまま載せた画像・書き写した数値)を、名前・出所・ライセンスとともに
一覧にする。作り直せそうなもの、転載の許諾が要るものに印を付ける。

### 4. 報告を書く

`docs/reviews/YYYY-MM-DD-thesis.md` にまとめて書き出す。

- 総評(3行以内)
- `docs/thesis-plan.md` の「全体の一貫性チェック」の各項目の判定(満たす / 満たさない / 確かめられない)と根拠
- 観点ごとの所見(重大 / 要修正 / 軽微、「原文の引用 → 修正案」)
- 撤回・中止・置き換え・進行中の実験に頼っている主張の一覧(無ければ「なし」)
- 手で書かれた数値・未定義の値・値の不一致の一覧
- R3 の一覧
- `docs/thesis-plan.md` と原稿の食い違い(原稿を正として、表をどう直すか)

### 5. 報告する

重大な課題の上位3件をその場で要約し、報告のパスを示す。原稿・`docs/thesis-plan.md` を直すのは、
ユーザーが望んだときだけにする。
