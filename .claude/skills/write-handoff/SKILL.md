# 引き継ぎを書く

完了を報告する前(結果・判断・ジョブ・次の作業が変わったとき)、長時間ジョブを投げる前、状態が大きく変わったときに使います。
目標はひとつ、**新しいセッションが `STATE.md` を入口に、ファイルだけで再開できること**です。

セッションがいつ終わるかは分からないので、「セッションの終わり」を待ちません。チャットの文脈は次のセッションにも、
Claude Code と Codex の切り替えにも残らず、エージェントの記憶(Claude Code の自動メモリなど)はもう一方のエージェントや
別の複製からは読めません。残す価値のある情報は、その場で正本のファイルに書きます。

## 手順

1. **`STATE.md` の変わった節をすべて更新する。**
   - 最終更新(日時 + 誰が)、段階、**現在の焦点(スタディ名を必ず書く)**。次のセッションはここに挙がったスタディの `EXP_SUMMARY.md` だけを読む
   - 実行中・待ちのジョブ: スタディ、ジョブ、**どう確認するか、結果をどこに書くか**まで書く。
     そのスタディの `projects/<study>/experiments/JOBS.md` に行があるか確かめる(状態と履歴は JOBS.md だけに書く)。
     「確認方法」が無いジョブは、次のセッションが放置するか二重に走らせる。終わったジョブは JOBS.md に結果を
     追記し、STATE.md の行を消す。
     ユーザーの作業待ち(過去の結果のコピーなど)も待ちの行として書く
   - 直近の決定事項: 決めたことと**理由**(今の段階のものだけ)
   - 未解決の問い: 次のセッションが考えるべきこと
   - 次の作業: 優先度を付け直し、終わった行は消す
   - ブランチやコミットの状態は書かない(`git status` と `git log` で分かり、書くとすぐ古くなる)

2. **今回の成果が正本のファイルに入っているか確かめる。**
   正本の場所は `AGENTS.md` の「単一の正本」の表にある(表はそこだけに置き、ここには写さない)。
   チャットにしか無いものがあれば、いま書く。特に次のもの。
   - 実験の結果 → その実験の `summary.md`(答え・言えないこと・主な数値と出所・本実行)と `README.md`、
     索引の行(一行で・状態・論文・由来)。同じコミットで
   - 撤回・訂正・置き換え → `AGENTS.md` の「実験」の「状態と撤回」の手順どおりか
     (`summary.md`・索引、撤回なら `docs/guardrails.md`、原稿)
   - 繰り返さない失敗 → `docs/guardrails.md`、新しい案・却下した案 → `docs/ideas.md`
   - 章の対応・根拠・執筆状況・研究段階の変化 → `docs/thesis-plan.md`
   - 指導教員・審査員の指摘への対応 → `docs/feedback/YYYY-MM-DD-<reviewer>.md` の状態欄

3. **取り込みの実験を確かめる。**
   各スタディの索引で由来が「取り込み」(再現性の無いもの)の行ごとに、その `summary.md` の「残りの手順」が
   今の状況どおりに印が付いているか、残りの手順(誰が何をするか)が書いてあるかを確かめる。
   ユーザーのコピー待ちなら、`STATE.md` の待ちの行か次の作業にもあるか確かめる。

4. **経緯を残す価値があれば、研究ログを書く。**
   分岐の多い調査、方針転換、長いデバッグのときは `docs/research-log.md` の
   `<!-- newest entry below -->` の直下にエントリを足す(`research-log` スキル)。
   恒久的な判断は `docs/decisions/_adr-template.md` を写して `docs/decisions/NNNN-<slug>.md` にする。

5. **常に読む文書を文字数の上限に収める。**
   `STATE.md` 6000字、`docs/thesis-plan.md` 8000字、`docs/guardrails.md` 8000字、各 `EXP_SUMMARY.md` 10000字、
   索引の行は1行200字まで(行数ではなく文字数で数えるので、行を長くしても収まらない)。古い決定は研究ログ・
   意思決定記録へ、実験の詳細はその `summary.md`・`README.md` へ、失敗の経緯は研究ログへ、論文で使わずに
   終わった完了・中止の実験の行は `EXP_ARCHIVE.md` へ移す(撤回の行と章で使う行は残す)。

6. **構造の検査を通す。**
   `docker compose exec research-template uv run pytest tests/test_repo_structure.py -q`(端末が無ければ `exec -T`)が
   通るまで直す。そのうえで、作業ブランチへのコミットを任されていればコミットする。任されていなければ、
   未コミットの引き継ぎがあることを報告に書く。

## 確認

`STATE.md` を**まっさらなセッションのつもりで読み直す。**
再開に要るもので欠けているものはないか。あれば足す。

特に確認すること。

- 現在の焦点にスタディ名が書いてあるか
- 実行中・待ちのジョブに「確認方法」と「結果の記録先」が書いてあるか
- 今回触れた実験の `summary.md` の状態と索引の状態欄が同じ語か
- 撤回が `docs/guardrails.md` と索引の両方に入っているか
- 由来が「取り込み」の行のすべてに、`summary.md` の「残りの手順」があるか
- 次の作業の P0 が、いま本当に最優先か
