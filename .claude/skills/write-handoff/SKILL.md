# 引き継ぎを書く

目標はひとつ、**新しいセッションが `STATE.md` を入口に、ファイルだけで再開できること**。チャットの文脈も
エージェントの記憶(Claude Code の自動メモリなど)も次のセッションやもう一方のエージェントには残らないので、
残す価値のある情報はその場で正本のファイルに書く。「セッションの終わり」は待たない。

## 手順

1. **`STATE.md` の変わった節をすべて更新する。**
   - 最終更新(日時 + 誰が)、段階、**現在の焦点(研究の `id` と章を必ず書く)**
   - 待ちの行: 研究リポジトリでの作業(図・数値を作る、結果を直す、コミットする)とユーザーの作業(`external/` の
     リンク、転載の許諾、指導教員の返事)。**誰が何をするか、どう確かめるか、終わったら何をするか**まで書き、
     終わった行は消す
   - 直近の決定事項と理由(今の段階のものだけ)、未解決の問い、次の作業(優先度を付け直し、終わった行は消す)
   - ブランチやコミットの状態は書かない(`git status`・`git log` で分かり、すぐ古くなる)

2. **成果が正本のファイルに入っているか確かめる。** 正本の場所は `AGENTS.md` の「単一の正本」の表にある
   (ここには写さない)。チャットにしか無いものがあれば、いま書く。特に次のもの。
   - 研究の並び・出典のコミット・状態 → `research.json`
   - 研究の要約・図表の元 → `projects/<id>/README.md`、本文の数値と元 → `projects/<id>/values.tex`
   - 実験・データ・計算の結果と撤回・訂正 → 研究リポジトリ(ここには書かない。頼む内容を待ちの行に書く)
   - 繰り返さない失敗・撤回した主張 → `docs/guardrails.md`、新しい案・却下した案 → `docs/ideas.md`
   - 主張・研究課題・貢献・マイルストーンの変化 → `docs/thesis-plan.md`
   - 指導教員・審査員の指摘への対応 → `docs/feedback/YYYY-MM-DD-<reviewer>.md` の状態欄

3. **経緯を残す価値があれば研究ログを書く**(`research-log` スキル)。章の構成の変更、根拠にする研究の選択、
   研究の更新で結論が変わったときなど。恒久的な判断は `docs/decisions/` の意思決定記録にする。

4. **常に読む文書を文字数の上限に収める。** `STATE.md` 6000字、`docs/thesis-plan.md` 8000字、
   `docs/guardrails.md` 8000字(文字数で数える)。古い決定は研究ログ・意思決定記録へ移す。

5. **確かめる。** 文字数は `wc -m STATE.md docs/thesis-plan.md docs/guardrails.md` で数える。スキル・`AGENTS.md`・
   Makefile も変えたときは `make test ARGS=tests/test_repo_structure.py` を通す。コミットを任されていれば
   コミットし、任されていなければ未コミットの引き継ぎがあると報告する。

## 確認

`STATE.md` を**まっさらなセッションのつもりで読み直し**、再開に要るもので欠けているものを足す。特に次を確かめる。

- 現在の焦点に研究の `id` が書いてあるか、`research.json` の `status` と食い違っていないか
- 待ちの行に「誰が何をするか」「どう確かめるか」「終わったら何をするか」が書いてあるか
- 研究リポジトリの結果をここの文書に写していないか(要約は `projects/<id>/README.md`、ほかは `<repo>@<sha>` で示す)
- 撤回した主張(送った版・投稿・発表で外に出たもの)が `docs/guardrails.md` に入っているか
- 次の作業の P0 が、いま本当に最優先か
