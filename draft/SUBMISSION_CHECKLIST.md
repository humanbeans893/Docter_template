# 提出前の確認項目

大学・研究科の最新版の提出要項を正とし、次を確認してください。この一覧は一般的な項目だけで、個別の大学の手続きは含みません。

## 書式

- [ ] 正式な学位名、題目、著者名、所属、指導教員名、提出日(`thesis-config.tex`)
- [ ] 表紙・背表紙・審査用の表紙の指定様式
- [ ] 用紙、余白、行間、片面／両面、フォント、ページ番号
- [ ] 和文・英文要旨の字数、キーワードの数、提出の順序
- [ ] 宣誓文、署名、関連論文・著者の貢献の要否(`thesis-config.tex` の任意ページのフラグ)
- [ ] 電子提出のファイル名、容量、PDF/A、暗号化の禁止などの要件

## 研究の誠実さ

- [ ] 研究倫理の承認番号、同意、データの利用許諾
- [ ] 利益相反、資金提供、謝辞、助成番号
- [ ] 共著論文を含む章の著者の貢献、転載の許諾、発表版との違い(各章の冒頭)
- [ ] データ・コードの公開先、DOI、公開の猶予期間、ライセンス
- [ ] 本文・要旨・図表・補足資料の数値がすべて `\val` か生成した表から組まれ、手で書いた結果の数値が無い
- [ ] 撤回・中止・置き換え・進行中の実験に基づく主張が残っていない(`make check` の W14 が無い)
- [ ] 取り込んだ過去の結果は、その取り込み実験が `完了`(入力の sha256 と既発表の数値との照合が通り、`summary.md` に記録した)になってから使っている
- [ ] R3 の生成物(`make check` の I3: そのまま載せた過去の図、書き写した数値)の一覧を指導教員と確認し、他者の図は転載の許諾を確認した
- [ ] 手で作った図がすべて `figures/README.md` の台帳にあり、出典とライセンスが書いてある

## 書誌

- [ ] `reference.bib` の全項目を DOI(無ければ ISBN か公式ページ)で原典と照合済みで、すべてに `verified` の欄がある
- [ ] 引用した数値を原文で確かめた
- [ ] 雛形の `lamport1994latex` と `main.tex` の `\nocite` を消した
- [ ] 同じ DOI の重複が無い(`make check` の W13)

## 技術的な検証

- [ ] `make test && make lint`
- [ ] 作業ツリーがきれいな状態で、生成物を作り直しても変わらない: `python3 tools/thesis_check.py --list-generators` が出すコマンドを上から順にすべて実行し(実験は `--overwrite` 付きで、上流が先に並ぶ。実験の前の `out/` は消える)、その後 `git status --porcelain -- 'projects/*/result/*' ':(exclude)*.provenance.json'` が何も出さない。由来記録(`*.provenance.json`)は作った日時(`created`)とコミット(`git_commit`)だけが変わるので、タグを付ける前にコミットする
- [ ] `make submission`(提出用の PDF と補足資料を作り、`make check-final` で2つを合わせて1回で検査する。どちらかで使っている図や書誌は、使っているとみなす)
- [ ] `make security-history`
- [ ] PDF を別の端末で開き、目次のリンク、フォント、図表、ページの順序を確認
- [ ] TODO、変更履歴、注釈、非表示のレイヤーが残っていない
- [ ] 未定義の参照・引用・値、Overfull box、重複したページのアンカーが無い

## 保存

- [ ] 提出する版のコミットにタグを付け、`make archive TAG=<タグ>` で `dist/<タグ>/`(両方の PDF、ソース、データの一覧、生成のコマンド、チェックサム)を作った
- [ ] データ台帳(`projects/<study>/data/README.md`)から全データを再取得できる
- [ ] 解析環境を `uv.lock` と `Dockerfile` から再構築できる
