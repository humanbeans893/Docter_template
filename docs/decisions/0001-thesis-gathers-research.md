# 0001 — 博士論文のリポジトリは研究を集めるだけにする

- **日付**: 2026-10-13
- **状態**: 採用

## 背景

以前の版は、実験の実行・データ・由来の記録・過去の結果の取り込みまでをこのリポジトリで扱っていた。実際の実験は研究ごとの別リポジトリで行われ、その形もそろっていない(research-template に従わないものもある)。仕組みとテストが大きくなるほど、エージェントにも人にも扱いにくくなった。

## 決定

- このリポジトリは、研究リポジトリの研究を集めて博士論文に仕上げることだけを行う。実験・データ・計算は研究リポジトリに残す。
- 研究の一覧と章の構成は `research.json`、1つの研究の中身は `projects/<id>/`(要約カード `README.md`・`figures/`・`tables/`・`values.tex`)という決まった形にそろえる。雛形は `projects/_template/`。
- 研究リポジトリからは、コミットした状態の図・表・数値を `cp` か `git show` で写し、元を `<repo>@<sha>:<path>` で書く。研究リポジトリとの整合を自動で追う仕組みは持たない。
- 力を入れるのは、エージェントの規約(`AGENTS.md`)とスキル(`add-research` など)、博士論文としての体裁(`draft/`)。検査は原稿の TeX に限る(`tools/thesis_check.py`)。

## 帰結

- どんな形の研究リポジトリでも、エージェントが同じ形に直して取り込める。リポジトリが小さくなり、テストも減る。
- 図・数値の由来は、写したときのコメントと `research.json` の `source` だけが頼り。研究リポジトリが後で変わっても自動では分からないので、更新は `add-research` スキルの手順で人が始める。

## 検討した他の案

- 研究リポジトリを固定したコミットで同期し、写したファイルの sha256 と実験の状態を検査する仕組み — 研究リポジトリの形をそろえる前提が要り、機能とテストが大きすぎた。
- 実験をこのリポジトリで行う(以前の版) — 実験は研究ごとのリポジトリで進んでおり、二重の管理になる。
