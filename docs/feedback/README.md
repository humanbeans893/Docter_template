# docs/feedback/ — 指導教員・審査員の指摘と対応

送った版ごとに受けた指摘を一つずつ記録し、どう対応したかを追えるようにする場所です。口頭やメールで受けた指摘も、ここに書くまでは対応の対象として扱いません。

## 版を送る

1. 送る版を作る: `make pdf-review`(全体。章だけなら `make pdf-review ONLY=02-study1`)。各ページの左上に、コミットと日付の印(`Review copy <短い sha>[-dirty] <YYYY-MM-DD>`)が付きます。`-dirty` が付く版は、作業ツリーに未コミットの変更があります。送る前にコミットします。
2. 送った時点にタグを付ける。タグの作成と push は本人が行います(エージェントは行いません)。

   ```bash
   git tag review/YYYY-MM-DD
   git push origin review/YYYY-MM-DD
   ```

3. `../../STATE.md` の「次の作業」か待ちの行に、返事を待っていることを書きます。

## 指摘を受けたら

1. `_template.md` を `YYYY-MM-DD-<reviewer>.md` に写します。日付は指摘を受けた日、`<reviewer>` は役割で書きます(例: `supervisor`、`examiner-a`)。
2. 指摘を1行ずつ表に入れます。箇所は、送った版の頁・行番号か、章・節・図のラベルで書きます。
3. 対応方針を決めます(直す / 説明を足す / 直さない理由)。迷うものは指導教員と確かめます。
4. 直したら、対応内容にコミットかラベルを書き、状態を進めます。結果や主張が変わる対応は、`../../AGENTS.md` の「実験」の「状態と撤回」の手順で直します: その実験の `summary.md` と索引 `projects/<study>/experiments/EXP_SUMMARY.md` の状態欄を同じコミットで直し、撤回なら `../guardrails.md` にも1行足します(送った版に載っていた主張の訂正・置き換えも、古い主張がすでに外に出ているので同じです)。`../thesis-plan.md` も同じ作業で直します。

状態の語: `未対応` / `方針確認中` / `対応中` / `対応済` / `見送り(理由)`。

## 前の版からの差分

前回送った版から何が変わったかは、タグとの差分で示せます。

```bash
git diff --word-diff review/YYYY-MM-DD -- draft/chapters draft/frontmatter
```

## 公開リポジトリでの注意

このリポジトリを公開するなら、指摘の原文に個人的な内容や未公開の情報が含まれる場合は要約して書きます。人名ではなく役割で書きます。
