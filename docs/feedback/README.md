# docs/feedback/ — 指導教員・審査員の指摘と対応

送った版ごとに受けた指摘を一つずつ記録し、どう対応したかを追えるようにします。口頭やメールで受けた指摘も、ここに書くまでは対応の対象として扱いません。

## 版を送る

1. `make pdf-review` で送る版を作る(1章だけ見てもらうときも全体を送り、読む章を伝えます)。各ページに `Review copy <短い sha>[-dirty] <YYYY-MM-DD>` の印が付きます。`-dirty` は未コミットの変更がある印なので、送る前にコミットします。
2. 送った時点にタグを付ける(タグの作成と push は本人が行います)。

   ```bash
   git tag review/YYYY-MM-DD
   git push origin review/YYYY-MM-DD
   ```

3. `../../STATE.md` の待ちに、返事を待っていることを書きます。

## 指摘を受けたら

1. `_template.md` を `YYYY-MM-DD-<reviewer>.md` に写します(日付は受けた日、`<reviewer>` は `supervisor`・`examiner-a` など役割)。
2. 指摘を1行ずつ表に入れます。箇所は送った版の頁・行番号か、章・節・図のラベルで書きます。
3. 対応方針(直す / 説明を足す / 直さない理由)を決めます。迷うものは指導教員と確かめます。
4. 直したら、対応内容にコミットかラベルを書き、状態を進めます。研究の結果そのものに関わる指摘は研究リポジトリでの作業になるので、`../../STATE.md` の待ちに書き、新しいコミットを `add-research` スキルで反映します。主張を取り下げたら `../guardrails.md` に1行足し、`../thesis-plan.md` も同じ作業で直します。

状態の語: `未対応` / `方針確認中` / `対応中` / `対応済` / `見送り(理由)`。

前回送った版からの差分は `git diff --word-diff review/YYYY-MM-DD -- draft/chapters draft/frontmatter` で示せます。

公開するリポジトリなら、個人的な内容や未公開の情報は要約し、人名ではなく役割で書きます。
