# 繰り返さないこと

この論文の研究で繰り返してはいけない失敗と、撤回した主張を記録します。毎セッションの最初に読むので、1件1行にし、詳しい経緯は該当する実験の `summary.md`・`README.md` や `docs/research-log.md` に書いてリンクします(全体で8000字まで。`tests/test_repo_structure.py` が検査します)。新しい失敗が起きたら、その場で行を足します。特定の実験の読み方や、その実験から言ってはいけないことは、その実験の `summary.md` の「言えないこと」に書きます。

## よくある落とし穴(一般則。この研究に合わせて削ってよい)

- 本番の実行を、最初の動作確認や性能の測定にしない(`--smoke` → 見積もり → 本番)。
- 結果を見た後に、実験の定義や評価の条件を変えない(変えるなら新しい番号の実験にする。結果を見てから決めた判定の規則は `summary.md` に「事後」と書く)。
- 未コミットの作業を放置したまま次の作業を積まない(コミット・退避・破棄のどれかに決める)。
- 環境のずれ(lock 外のインストール、コンテナ外の実行)に気づかないまま結果を比べない。
- 乱数の種・設定・コミットを記録していない実行結果を信用しない(実験なら `out/params_used.json` を見る)。
- 数値を README や原稿へ手で書き写さない。CSV からコードで生成する。書き写しは桁や小数を間違え、CSV の検査が通っても手で書いた数値は古いまま残る。`summary.md`・`README.md` に書く数値には出所(CSV・行・列)を添える。
- 既定値に頼ったまま結論を書かない。評価する時点・閾値・期間などの既定値を変えても結論が保たれるかを確かめてから書く。
- 同じ量を、別の推定量や別の分母で比べない。比べる2つは同じ定義・同じ集合で計算する。
- 本文を直したら、補足資料・付録・図表の説明・要旨も同じ作業で直す。片方だけ直すと食い違いが残る。
- 原稿を縮めるときは、主張の限定(条件・例外・頑健でないこと)を一緒に落としやすい。縮めた後に限定が残っているかを確かめる。
- 図の重なりや見え方を、文字や画像の配置の計算だけで「問題なし」と報告しない。描画した画像を実際に見て確かめる。

## 博士論文で特に起きやすいこと

- `experiments/*/out/` や `data/` の下の図を `\includegraphics` しない。`out/` は Git に入らず、新しい複製では図が消える。コードで `result/` へ昇格する(`make check` の E10)。
- 結果の数値を本文に打ち込まない。要旨・結論・図表の説明の数値も `\val{…}` で読む。値のファイルは `draft/values.tex` に登録し、章の中で `\input` しない(要旨は章より前に組まれる。E11)。
- ある章の結果が変わったら、和英の要旨・結論・`docs/thesis-plan.md` を同じ編集で直す。章を直しただけで終えない。
- 取り込んだ過去の結果は、その取り込み実験が `完了` になるまで(入力と既報の数値の照合が通り、`summary.md` に書くまで)本文で使わない(`make check` の W14 が `進行中` を知らせる)。
- 合成データ・サンプル・デモの出力を結果として使わない。古いリポジトリで撤回・中止になった結果を黙って取り込まない。
- R3(画像や論文中の数値をそのまま載せたもの)は意識して記録した例外にする。`make check` の I3 の一覧を指導教員と確かめ、作り直せるものは作り直す。
- 解析の図を `draft/figures/` に置かない(手作りの図だけ。台帳 `draft/figures/README.md` に行を足す)。
- 未コミットのコードや、実行中に変えたコードで作った図表を提出版に残さない(W15)。提出の前に、すべてをコミットしたきれいな作業ツリーで `python3 tools/thesis_check.py --list-generators` のコマンド(実験は `--overwrite` 付きで、上流が先に並ぶ)をすべて上から実行し直し、`git status --porcelain -- 'projects/*/result/*' ':(exclude)*.provenance.json'` が何も出さないことを確かめる。生成物には日時もコミットも入らないので、出たものは本当の違い。由来記録は作成日時とコミットだけが変わるので、確かめたらコミットする。
- `draft/` の中で `lualatex` を手で実行しない。残った `.aux`・`.bbl` が黙って読まれ、参照の欠けた PDF ができる。
- 長時間のジョブが動いている間に `make up` などでコンテナを作り直さない。`docker compose exec` のジョブはすべて止まる。
- 書誌を推測で作らない。DOI で原典を確かめてから `reference.bib` に入れ、`verified` の欄を付ける。
