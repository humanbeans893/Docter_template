# 長時間ジョブの投入前チェックリスト

高コストな計算(HPC のジョブ、長時間の学習・解析、課金のあるクラウドでの実行)の前に、毎回このリストを上から確かめます。1項目でも欠けたら投入しません。本番の実行を最初の動作確認や性能の測定にしないことが原則です。

## 起動の前提(コードが最初に踏む地雷)

- [ ] `run.py --smoke` を最後まで通した(`params.SMOKE` の小さな入力で同じコードを通す。設定の読み込み・必須の値・型の誤りは起動直後に落ちる)。
- [ ] 関係するテストが通っている(`docker compose exec research-template uv run pytest projects/<study>`)。
- [ ] 必要な入力データと上流の成果物がすべてあり、パスが解決できる。過去の結果を使うなら `verify_inputs` の照合が通る。

## 再現性

- [ ] 作業ツリーがきれいで、意図したコミットにいる(`pwd && git branch && git status`)。`summary.md` の問いと判定の規則・`params.py`・`run.py` と変えたコードをコミットした。実行中はコードを変えず、コードに触れるコミットもしない(原稿・文書は構わない)。同じスタディで次に使う実験は投入の前に作ってコミットしておく(実行中に作ると、それ以後の生成物は未コミットの扱いになり W15 が出る)。
- [ ] 環境が固定されている(`uv.lock`、イメージ、モジュールの版)。
- [ ] 乱数の種を含む設定一式が実験の `params.py` に固定されている(`config.py` や環境変数から読まない)。シード・パラメータ・コミット・未コミットのファイルの一覧は `out/params_used.json` に残る。

## 実行の設計

- [ ] 完了した本実行を残すなら新しい番号の実験にする(`--overwrite` は前の `out/` を始めに消す。`result/` は本実行が通るまで前のまま)。
- [ ] 出力は `run.out()`・ヘルパー・`run.promote()` だけで書き、成果物のディレクトリに直接書かない。他の実験の `result/tables/*.csv` や `data/processed/NNN_<slug>/` を読むなら、ヘルパーと `run.promote()` に `sources=[...]` で渡している(渡さないと、上流を撤回しても `make check` の W14 が出ない)。
- [ ] `--smoke` の段階ごとの所要時間から、本番の所要時間と資源を見積もった。
- [ ] 長時間のジョブは、途中保存と再開を確かめてある。
- [ ] 資源の要求(ノード・GPU・上限時間・ディスク)が見積もりと合っている。
- [ ] ローカルの Docker で動かすなら、実行中にコンテナを作り直さない(`make up`・`make build` の後の起動で `docker compose exec` のジョブは止まる)。他のジョブが動いていないかを `docker compose top` で確かめた。同じ出力先の実行は一度に1つで、ロックは1台(1つのコンテナ)の中でしか効かない(HPC の共有ファイルシステムの上で、別の計算機から同じ実験を動かさない)。

## 投入直後と完了後

- [ ] 投入直後: そのスタディの `experiments/JOBS.md` に行を足し、`STATE.md` を更新した(`write-handoff` スキル。確認方法と結果の記録先まで書く)。
- [ ] 完了後: 結果を `experiments/JOBS.md` に追記し、結論を `NNN_<slug>/summary.md` と索引の行に、経緯を `README.md` と `docs/research-log.md` に(同じコミットで)記録した。`STATE.md` の行を消した。
- [ ] 失敗したとき: 失敗も記録として残した(`params_used.json` が `failed` なら、そのまま `--overwrite` なしで実行し直せる。コンテナの作り直しで止まった実行は `running` のまま残り、次の実行が片づける。公開の途中で止まったら `make check` が E12 を出すので、`make pdf` の前にもう一度本実行して元に戻す)。繰り返さない失敗なら `docs/guardrails.md` に1行足した。
